# Радиодозор

**Локальный стенд Wi-Fi-зондирования на ESP32-S3.** Платы передают измерения радиоканала (CSI) ноутбуку. В браузере видны изменения I/Q, события движения и экспериментальная оценка дыхательного ритма.

## Быстрый старт

Скачайте исходники через **Code → Download ZIP** на GitHub или клонируйте репозиторий.

```bash
git clone https://github.com/EEGRINO/radiodozor.git
cd radiodozor
```

1. Установите [Python 3.11 или новее для Windows](https://www.python.org/downloads/windows/).
2. Дважды щёлкните [**`Start-Windows.cmd`**](Start-Windows.cmd) или запустите его из PowerShell.

```powershell
.\Start-Windows.cmd
```

При первом запуске скрипт создаёт `.venv` и загружает зависимости с PyPI. Затем открывается [Радиодозор](http://127.0.0.1:8010/). Панель доступна и без плат. После установки зависимостей приложение работает без интернета. Для остановки нажмите **Ctrl+C** в окне запуска.

## Подключение ESP32

Для стенда с двумя радиолиниями используйте две **ESP32-S3**, роутер с Wi-Fi **2,4 ГГц** и ноутбук в той же подсети. Для измерений по одной линии достаточно одной платы и роутера.

1. Залейте на платы прошивку с форматом **RUV2**. [Прошивка и профили плат](https://github.com/EEGRINO/wifi-densepose/blob/main/docs/technical.md#прошивка-платы-для-начинающих).
2. В настройках каждой ESP укажите локальный IPv4 ноутбука и UDP-порт **5555**. В Windows адрес покажет `ipconfig`. [Настройка новой платы](https://github.com/EEGRINO/wifi-densepose/blob/main/docs/technical.md#первый-запуск-и-captive-portal).
3. Запустите Радиодозор. Проверьте, что счётчик кадров растёт и в списке **«Радиолиния»** появились приёмники.

### Запуск рядом с WiFi DensePose

Если WiFi DensePose уже принимает CSI на UDP 5555, запустите Радиодозор через его WebSocket `/visor`. Настройки плат при этом сохраняются.

```powershell
.\Start-Windows.cmd --from-visor ws://127.0.0.1:8765/visor
```

Мост получает последние кадры каждой линии. Для испытаний, которым нужен весь входящий поток, используйте прямой приём UDP.

## Экраны и возможности

| Режим | Для чего |
| --- | --- |
| **Охрана помещения** | Наблюдать след ΔI/ΔQ, откалибровать пустую комнату и включить тревогу по движению или устойчивому ритму |
| **Опека · сон** | Записать отдельный фон, посмотреть график и силу дыхательного сигнала, увидеть кандидата пульса при устойчивом спектральном пике |

В обоих режимах начните с **«Записать пустую комнату»**. После 12 секунд на выход из комнаты идёт 45-секундная запись фона. Для оценки ритма требуется около 40 секунд устойчивого CSI. После смены положения плат, мебели или Wi-Fi-канала запишите фон заново.

Оценки зависят от расстановки устройств, качества приёма и помех. Вентилятор может дать периодический сигнал. Точность оценок и частоту ложных тревог нужно измерять отдельно для каждого стенда. Режим сна предназначен для экспериментов, а пульс отображается как кандидат по спектру CSI. [Порядок измерений и проверки](docs/technical.md#проверка-стенда).

## Диагностический журнал

Кнопка **«Скачать журнал»** сохраняет события в JSONL. Файл `data/events.jsonl` пополняется при калибровке, смене режима и срабатывании тревоги. Файлы `data/baseline.json` и `data/sleep_baseline.json` хранят фон для каждого режима и загружаются при старте. После перезапуска тревога выключена.

## Решение проблем

| Симптом | Что проверить |
| --- | --- |
| Установка остановилась | Версию Python и доступ к PyPI. Сообщение об ошибке остаётся в терминале запуска |
| UDP 5555 занят | Остановите предыдущий приёмник или подключитесь к его `/visor`, если запущен WiFi DensePose |
| HTTP 8010 занят | Остановите предыдущий запуск или укажите другой порт, например `--port 8011` |
| Интерфейс открыт, кадры отсутствуют | Питание ESP, общий роутер, IPv4 ноутбука и правило брандмауэра для UDP 5555 |
| Ритм или пульс отображается прочерком | Наличие сохранённого фона, поступление CSI и достаточное окно спокойного сигнала |

## Документация

[Техническое руководство](docs/technical.md) описывает поток CSI, режимы измерения, параметры запуска, проверку стенда и план сравнения ESP32-S3 с ESP32-C5.

| Файл или каталог | Содержимое |
| --- | --- |
| [`csi.py`](csi.py) | Разбор UDP-кадров RUV2 и ответов `/visor`, нормирование амплитуд |
| [`sensing.py`](sensing.py) | Фон, порог движения, спектральная оценка дыхания и кандидата пульса |
| [`server.py`](server.py) | Приём CSI, управление режимами, локальный HTTP-сервер и журнал |
| [`static/`](static/) | Панель наблюдения и обзор I/Q |
| [`tests/`](tests/) | Проверки обработки CSI на синтетических данных |

После установки зависимостей тесты можно запустить из PowerShell.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Источники и лицензии

- Формат RUV2 и обзор I/Q адаптированы из [EEGRINO/wifi-densepose](https://github.com/EEGRINO/wifi-densepose). В обзоре используются развёртка поднесущих, компенсация общего поворота фазы и затухание следа. [Уведомления исходного проекта](https://github.com/EEGRINO/wifi-densepose/blob/main/THIRD_PARTY_NOTICES.txt).
- Порядок сравнения оценок дыхания с опорными измерениями описан в [BreatheSmart](https://pmc.ncbi.nlm.nih.gov/articles/PMC9830631/). В [FarSense](https://arxiv.org/abs/1907.03994) применено отношение CSI двух антенн, а [PulseFi](https://arxiv.org/abs/2510.24744) использует собственную обработку и обученную модель. Результаты этих работ относятся к их алгоритмам и аппаратуре.
- Лицензии зависимостей опубликованы в репозиториях [NumPy](https://github.com/numpy/numpy/blob/main/LICENSE.txt) и [websockets](https://github.com/python-websockets/websockets/blob/main/LICENSE).
